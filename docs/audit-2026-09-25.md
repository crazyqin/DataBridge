# DataBridge 补充审查（2026-09-25）

本轮基于当前工作区代码和上一轮构建的 `databridge:standalone-amd64`，使用独立临时数据库、HTTP 请求、受控并发和 Chromium 浏览器验证。未修改业务代码、生产数据或部署。以下是本轮发现，不代表已穷尽所有缺陷。

**后续处理状态：**A01–A16 已在本次修复并通过独立数据库、完整后端测试和浏览器/并发复测。下面的复现结果保留为修复前证据；“风险点”部分仍是独立的后续评估清单。

## 已复现的缺陷

### A01 高：数据源停用后，旧配置可能重新进入连接池缓存

- 查询的 REPEATABLE_READ 事务已经读取旧配置、尚未初始化数据源连接池时，另一个请求停用数据源并清理缓存；原请求随后从旧事务快照创建连接池。
- 实测停用返回 200，数据库 `enabled=false`，随后三个全新匿名查询仍全部返回 200 和源数据。不是仅有在途请求返回旧结果。
- `DatasourceService.pool()` 只在缓存不存在时检查 enabled，缓存没有配置版本；API 的 configVersion 也不随数据源变更更新。
- 位置：`backend/src/main/java/com/databridge/DatasourceService.java:49`、`:58`；`OpenQueryService.java:25`。
- 修复方向：数据源缓存绑定配置版本，配置读取与缓存发布协调；后续调用校验启用状态和版本，拒绝发布过期连接池。

### A02 高：公开慢查询耗尽平台连接池，管理后台不可用

- 每个外部 REALTIME 查询都在平台数据库事务中执行，并一直持有平台连接；平台池上限仅为 10。
- 用四个独立数据源配置并发执行十个 `pg_sleep(45)` 查询，确认十个查询都在执行；此时 `/admin/session` 等待 30.01 秒后返回 500。日志确认 `total=10, active=10, idle=0`。
- 位置：`backend/src/main/java/com/databridge/OpenQueryService.java:25`；`backend/src/main/resources/application.yml:7`。
- 修复方向：实时源查询避免长时间占用平台事务，使用配置版本验证保持一致性；增加开放查询并发上限和后台资源隔离。

### A03 高：旧编辑页面能覆盖最新鉴权配置

- GET 返回 configVersion，但配置保存没有比较客户端版本，只锁定后覆盖全部字段。
- 实测先把 PUBLIC 改为 API_KEY，匿名访问返回 401；随后提交旧页面中仅修改名称的完整配置，保存返回 200，authMode 被覆盖回 PUBLIC，匿名访问恢复 200。
- 位置：`backend/src/main/java/com/databridge/ApiService.java:91`；`frontend/src/views/ApiEdit.vue:24`。
- 修复方向：配置编辑加入乐观锁，旧版本提交返回 409 并要求重新加载。数据源配置也需要相同检查。

### A04 中：手工记录编辑存在丢失更新

- 两个页面读取同一记录；第一个修改 a，第二个只修改 b，却提交包含旧 a 的整条记录。两次保存都成功，a 的新值被旧值覆盖。
- 实测最终结果为 `{a:"old-a",b:"new-b"}`，第一次已保存的 `new-a` 丢失。
- 位置：`backend/src/main/java/com/databridge/ApiService.java:241`；`frontend/src/views/DataMaintain.vue:44`。
- 修复方向：记录增加版本号/ETag，更新检查版本；不能只依靠 API 配置行锁保证编辑一致性。

### A05 中：并发刷新遗留定时任务，停用后仍然同步

- refresh 中 cancel、读取配置、创建任务、tasks.put 不是一个原子操作，ConcurrentHashMap 不能保证这组操作互斥；sync 本身也没有检查 enabled。
- 并发启用同一快照接口后再停用，停用返回 200。等待在途任务结束后，enabled 仍为 false，但 last_sync_at 和快照记录 ID 继续更新。
- 位置：`backend/src/main/java/com/databridge/ApiService.java:136`、`:151`。
- 修复方向：按 API 串行更新任务，任务执行前重新验证启用状态及调度版本。

### A06 中：TIME 精度及带时区时间信息丢失

- `TIME '10:20:30.123456'` 返回 `10:20:30`；`TIMETZ '10:20:30.123456+08:00'` 返回 `02:20:30`；TIMESTAMPTZ 返回没有偏移标记的 UTC 墙上时间。
- 两个仅小数秒不同的 TIME 值作为快照唯一键时，同步返回 400 `duplicate snapshot unique key`。
- 位置：`backend/src/main/java/com/databridge/SqlService.java:123`、`:128`、`:145`。
- 修复方向：依据 JDBC 类型读取 LocalTime/OffsetTime/OffsetDateTime 等，定义并保留精度、时区的传输约定。

### A07 中：声明了类型的可选 SQL 参数，缺省时仍不能正确绑定

- `SELECT 1 AS id WHERE :p IS NULL OR 1 = :p`，p 声明为可选 integer。未提供 p 时返回 502，PostgreSQL 报 `could not determine data type of parameter $1`。
- 原因是空值只通过 setObject(index, null) 绑定，未使用参数定义提供的 SQL 类型。
- 位置：`backend/src/main/java/com/databridge/SqlService.java:103`、`:114`。
- 修复方向：为所有参数保留 JDBC 类型，并对 null 使用带类型绑定。

### A08 中：SQL 校验及参数转换尚未覆盖 PostgreSQL 方言

- `SELECT $$abc:def$$ AS label` 可保存，但调用返回 400，冒号被误识别为参数。
- `SELECT '{"k":1}'::jsonb ? 'k' AS present` 可保存，但调用返回 502，JSON 存在性操作符与 JDBC 占位符处理不兼容。
- `SELECT E'it\'s' AS text` 是合法 PostgreSQL 查询，但保存返回 400 `SQL string is not closed`。
- 位置：`backend/src/main/java/com/databridge/SqlService.java:39`、`:104`。
- 修复方向：统一方言感知的 SQL 词法、命名参数转换和 JDBC 转义；不能仅更换校验解析器。

### A09 中：等值过滤不支持真实 null

- 可选整数和字符串都保存 null 后，POST 过滤 `{n:null}` 返回 400；过滤 `{s:null}` 返回 200 但零条数据。
- 原因是所有过滤值都进入普通类型转换：整数解析 "null" 失败，字符串变成了字面文本 "null"。
- 位置：`backend/src/main/java/com/databridge/ApiService.java:287`；`SqlService.java:84`。
- 修复方向：显式区分 null、字段未提供和字符串 "null"，并统一过滤约定。

### A10 中：SQL 异常日志会包含请求参数原文

- 查询 `SELECT CAST(:input AS INTEGER) AS value`，参数为 string；提交非数字标记字符串后返回 502，该字符串出现在容器日志的 PostgreSQL 异常中。
- 开放接口返回值经过简化，但完整 SQLException 仍写入应用日志，可能包含敏感参数或源数据片段。
- 位置：`backend/src/main/java/com/databridge/SqlService.java:137`、`:140`。
- 修复方向：按 SQLState、错误类别和 request ID 记录脱敏摘要；限制详细诊断日志的开启及访问。

### A11 中：手工新增按钮允许重复提交

- 浏览器中一次双击“保存”，在普通请求延迟下生成两条完全相同的手工记录。
- saveManual 没有提交中状态或重入保护，后端每次创建随机 UUID，因此不会判重。
- 位置：`frontend/src/views/DataMaintain.vue:44`、`:61`。
- 修复方向：提交期间禁用按钮并阻止重入；需要处理重试语义时增加幂等键。

### A12 中：日志时间筛选使用浏览器本地时间，但后端按服务器时间解释

- Chromium 设置 Asia/Shanghai，选择 15:29 至 15:31；前端发送不带时区的同值字符串。
- 数据库 UTC 时间 07:30 的日志没有被查出；改用 07:29 至 07:31 才能查到。默认容器为 UTC，产生八小时偏差。
- 位置：`frontend/src/views/ApiLog.vue:13`；`backend/src/main/java/com/databridge/ApiService.java:299`。
- 修复方向：使用带偏移的时间或统一 UTC Instant，前端显示时再转换为用户时区。

### A13 低：清空日志日期后查询报错

- 浏览器选择日期再点击清空，发送 `?from=null`，返回 400 `invalid log time range`。
- load 只跳过 undefined 和空字符串，没有跳过日期控件清空产生的 null。
- 位置：`frontend/src/views/ApiLog.vue:7`。

### A14 低：快照页面仍会错误显示大整数

- 快照数据库值为 `9007199254740993`，浏览器表格显示 `9007199254740992`。本次测试中存储值保持正确。
- 手工记录列表已有无损数字传输，但快照列表和 SQL 测试结果仍使用普通 JSON.parse 的 number。
- 位置：`backend/src/main/java/com/databridge/ApiService.java:192`；`frontend/src/api.ts:38`；`frontend/src/views/DataMaintain.vue:55`。
- 修复方向：统一管理端数值传输约定，避免页面展示和复制出错。

### A15 低：字段定义校验接受缺失名称和错误的 required 类型

- `manualSchema:[{type:"string"}]` 保存成功，随后生成字段名为字符串 `"null"` 的记录。
- required 为字符串 `"true"` 也保存成功，但字段缺失时不执行必填检查。必填字符串还允许空字符串，应明确业务约定。
- 位置：`backend/src/main/java/com/databridge/ApiService.java:107`、`:273`。
- 修复方向：使用明确的请求 DTO/类型校验，名称不能通过 String.valueOf(null) 转换。

### A16 低：输入错误状态码和提示不准确

- `/admin/logs?apiId=abc` 返回 500，而不是 400。
- 101 字符的 API 名称触发字段长度限制，却返回 409 `API code or path already exists`。
- 位置：`backend/src/main/java/com/databridge/ApiErrorHandler.java:21`；`ApiService.java:49`、`:100`；`backend/src/main/resources/db/migration/V1__init.sql:9`。
- 修复方向：处理请求绑定/JSON 格式异常，提前验证长度，区分唯一性冲突和其他数据完整性错误。

## 基于代码或部署配置确认的风险点

这些项目的配置缺口可以确认，但影响取决于负载、代理、数据规模和使用方式；没有将其视为已经发生的事故。

1. **登录和开放查询缺少应用层限流。** 登录无失败次数限制，开放请求无总并发/速率配额。若入口代理也未限制，会放大暴力尝试、BCrypt CPU 消耗和 A02。位置：`SecurityConfig.java:37`、`OpenController.java:16`。
2. **日志无限增长，管理页面只能读最新 500 条。** 未发现清理/保留策略，未知路径和鉴权失败也写日志；大量匿名请求能持续增加数据库与容器日志。旧日志没有独立分页。位置：`PlatformRepository.java:97`、`:101`；`OpenController.java:43`。
3. **结果仅限制行数，未限制总字节和单值大小。** 大 JSON、数组、CLOB/BLOB 会完整读入内存；快照管理一次加载全部行，最大可达 100000 行。需评估内存、响应大小和浏览器渲染上限。位置：`SqlService.java:115`、`:160`；`PlatformRepository.java:91`；`DataMaintain.vue:30`。
4. **手工配置保存总是扫描全部记录。** 即使只改名称也执行 migrateManualRows，长期持有 API 行锁；某些 Java 类型在转换前后 equals 不等，还会产生不必要 UPDATE。无行数上限时，会拖慢配置修改和手工维护。位置：`ApiService.java:98`、`:115`。
5. **破坏性配置变更缺少页面提示。** 模式切换立即删除本地数据和排序，删除手工字段会清除历史字段值；保存前没有影响预览或专门确认，也没有恢复入口。位置：`ApiService.java:94`；`frontend/src/views/ApiEdit.vue:25`、`:56`。
6. **超时和调度隔离不足。** 查询设置 statement timeout，但没有统一网络读超时；调度线程只有两个，慢数据源可能拖延其他快照。Cron 使用服务器默认时区，默认容器 UTC 与本地预期可能不同。位置：`SqlService.java:110`；`DatasourceService.java:67`；`DataBridgeApplication.java:22`；`ApiService.java:141`。
7. **HTTPS 反向代理设置需要补齐/验证。** 当前配置只有 SameSite，没有明确 Secure 或 forwarded header 策略。带 X-Forwarded-Proto:https 的测试请求仍得到没有 Secure 的会话 Cookie；应结合实际可信代理配置验证。位置：`backend/src/main/resources/application.yml:13`。
8. **密钥生命周期和恢复能力有限。** 所有受保护 API 共用一个 Key，无法单独撤销客户端；已有数据卷丢失 `.app_secret_key` 时脚本会生成新密钥继续启动，原数据源密码无法解密；没有密钥版本迁移/轮换流程。位置：`SecurityConfig.java:24`；`docker/standalone-entrypoint.sh:34`。备份必须同时覆盖数据库和原密钥。
9. **平台数据库账号权限过高。** 实测独立镜像中的应用账号 databridge 是 PostgreSQL superuser；Compose 同样复用初始化账号。应用缺陷一旦演变成任意数据库操作，影响范围会被扩大。位置：`docker/standalone-entrypoint.sh:50`；`docker-compose.yml:8`、`:29`。
10. **交付和运维验证尚不完整。** 应用容器没有健康探针；镜像构建跳过测试，基础镜像使用浮动标签。仓库中未见完整备份恢复演练、依赖/镜像安全扫描及 MySQL/Oracle 实库兼容测试。位置：`Dockerfile:1`、`:13`；`Dockerfile.standalone`；`docker-compose.yml`；`backend/src/test/java/com/databridge/PlatformIntegrationTest.java`。
